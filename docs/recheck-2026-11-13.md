## 已修复的问题

| 级别 | 触发条件与原表现 | 修复与证据 |
| --- | --- | --- |
| P1 | 自启动操作失败时，配置已先落盘、前端却回滚，系统/磁盘/界面不一致 | 系统操作成功后再保存；保存失败补偿自启动状态；不改自启动时不触碰 OS。Rust 用例注入注册操作与写入失败，验证旧文件保留 |
| P1 | 多个设置修改排队时，前一个请求可能提前包含后一个补丁；失败可能回滚到从未保存的值 | 每次操作只提交自己的补丁，成功后采用后端返回的规范化设置；同字段连续失败与前成功后失败均有回归 |
| P1 | 自定义节点增删后，前端仍保留旧列表；下一次设置保存可能删除新节点或恢复已删节点 | 节点命令与设置保存共用队列，并同步后端状态；通用保存保护当前节点列表。隔离原生 IPC 实测了增加后旧快照保存、删除后旧快照保存 |
| P1 | 部分事件订阅失败却已标记 bound=true；再次绑定无效，或重试产生重复监听 | 绑定成功后才标记，合并并发绑定；第二个订阅失败时撤销第一个。窗口重新聚焦可重连测速事件；单元用例验证失败重试、撤销、并发 |
| P1 | 慢速“是否运行”查询晚于 finished 事件返回，将已完成状态重新改为运行 | 对账请求记录事件版本和请求序号，丢弃过期响应；恢复新的后台测速时清除上次结果与计时。用例验证查询与事件交错 |
| P1 | 准备阶段立即取消，默认零值仍被计算成高分/优秀；历史 HTML 也可能沿用旧评级 | 取消结果不生成质量评级，质量页解释未完成，详情与 HTML 不展示旧取消评级。原生取消实测质量字段为 null、质量页不绘制评级雷达 |
| P2 | 丢包未知被映射为 0%，雷达图绘成满分；未知上传绘成低分 | 指标支持 null，未知维度不绘制数据点/填充面积，真实 0% 保留为实测满分。页面与归一化用例覆盖 |
| P2 | 自定义节点允许 HTTP，但“使用”命令仍一律拒绝 HTTP | 仅允许匹配已保存、明确授权 HTTP 的自定义节点；任意其他 HTTP 地址继续拒绝。Rust 与原生 IPC 均验证 |
| P2 | 当前节点删除后仍保留手动 URL；“当前”标记取上一次测速节点，可能错指 | 删除所选节点时转自动优选并清空默认地址；选择状态取实际设置。原生 IPC 验证删除后模式 |
| P2 | 暂停 IPC 失败但按钮已变成“恢复”；Ping 页面返回后输入框仍显示默认目标 | 暂停成功后才提交状态；恢复真实 Ping 主机；操作中禁用重复点击与目标编辑，错误可见。单元测试和原生监控页验证 |
| P2 | 停止/替换 Ping 时，旧探测完成后仍可能发出一个旧样本 | 发事件前复核取消令牌；代码审阅与监控停止实测。未做底层 ICMP 调用的超时故障注入 |
| P2 | 慢历史回填用较旧数组替换实时缓存，最新点和最新速率倒退 | 按时间戳合并与去重，同时间保留实时样本；用例验证较旧回填不覆盖最新点 |
| P1 | 配置第二次损坏时先删除已有 .bak，丢失上一次恢复点 | 保留原 .bak，后续写入 .bak.1、.bak.2；备份失败不再声称成功。隔离文件用例验证已有备份与新损坏内容均保留 |

主要实现文件：`src-tauri/src/settings.rs`、`commands.rs`、`engine/mod.rs`、`pingmon.rs`、`report.rs`；`src/store/app.ts`、`test.ts`；`src/pages/ServersPage.tsx`、`MonitorPage.tsx`、`QualityPage.tsx`、`HistoryPage.tsx`；`src/components/RadarChart.tsx`、`src/App.tsx`、`src/api.ts`。

## 仍存在的不足

1. **P2 高频监控历史容量**：后端和前端仍以 3600 点兜底，200ms 采样时只能保留约 12 分钟，1 秒默认采样才接近 1 小时。需要时间分桶或分层降采样，同时验证内存、曲线代表性和设置切换；本轮未通过扩大内存来掩盖问题。
2. **P2 全范围历史图表**：统计卡已是全范围，日均/趋势/热力图仍基于已加载记录。界面已说明，后续可加入后端分桶聚合。
3. **P2 设置保存等待体验**：为保证失败一致性，界面采用保存成功后的权威状态；慢磁盘上可进一步加保存中反馈和高频滑块合并，保持同样的失败语义。
4. **P2 长期与平台验证**：尚缺休眠唤醒、网卡切换、系统缩放/辅助功能、真实 OS 自启动错误、磁盘满和超大历史库压力测试。
5. **发布与依赖审计**：本轮重试 npm 在线审计仍受网络阻断，上一轮 Rust 审计保留 5 项警告。本轮没有改锁文件，也没有重新宣称零漏洞；安装/更新链路仍需独立验收。

本轮确认并修复了上述具体缺陷，但不能据此保证项目已不存在其他 bug。
