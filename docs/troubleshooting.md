# 故障排查

## 应用无法启动

1. 确认系统为 Windows 10/11 x64。
2. 确认 WebView2 Runtime 已安装；安装器会在缺少运行时的环境中引导安装。
3. 重新启动应用，确认没有被同一应用的旧窗口遮挡。
4. 如果问题只在某个用户配置下出现，退出应用后备份并重命名 `%APPDATA%\com.netvisionpro.app\settings.json`，让应用重新生成默认设置。

## 测速没有结果或节点不可用

- 在“测速节点”页点击“重新检测节点”，确认至少有一个节点显示“可用”。
- 受限网络可能无法访问国际节点；添加可访问的本地 LibreSpeed HTTPS 节点。
- Cloudflare、LibreSpeed 和 M-Lab NDT7 的服务端策略不同，自动优选可能选择与上次不同的协议或位置。
- NDT7 节点依赖 Locate 服务和 WebSocket 端点；如果网络拦截 WebSocket，改用 LibreSpeed 或 Cloudflare 节点。
- 不要把网卡协商速率当作宽带测速结果；应用会将二者分开显示。

## 速度偏低或波动很大

- 关闭其他大流量下载、云盘同步和视频上传后重测。
- 在“网络质量”页比较空闲延迟与负载延迟，判断是否存在 Bufferbloat。
- 依次尝试自动优选、附近节点和自建节点；单个远端节点不代表本地宽带的全部能力。
- 延长测速时间或开启精度模式，减少短时间窗口的波动。
- Wi-Fi 环境先确认信号质量；有条件时使用以太网对照。

## 丢包、Ping 或路由显示未知

- 许多服务器和中间设备会丢弃 ICMP；未知不等于 HTTP 不可用。
- Windows 防火墙、运营商策略和目标服务器 ACL 都可能影响 ICMP。
- 通过“网络诊断”分别执行 HTTPS、TCP 和 ICMP 检测，不要只根据一项判断网络是否断开。
- 路由追踪对超时跳如实显示，不会用相邻跳结果替代。

## DNS 或 IPv6 检测失败

- DNS 检测包含系统解析和对配置 DNS 服务器的直接探测，UDP 53 被拦截时可能失败。
- IPv6 检测需要本机接口、默认路由和目标端点均支持 IPv6。
- 先在“网络诊断”页点击“刷新信息”，再重试主动检测。

## 历史记录或导出异常

- 历史保存在 `%APPDATA%\com.netvisionpro.app\history.db`，确认当前用户有读写权限。
- 历史页导出默认最多处理最近 5000 条记录，超过部分会提示截断。
- 清空历史是永久操作，执行前先导出 CSV、JSON 或 HTML 报告。
- 设置文件损坏时，应用会将其备份为 `settings.json.bak` 并恢复默认值；历史数据库不会因此自动删除。

## Prometheus 端点无法访问

- 确认设置页已开启指标导出，并使用页面显示的实际端口。
- 端点只监听 `127.0.0.1`，从其他设备访问属于预期不可用。
- 端口必须在 1024–65535 范围内，若端口被占用请更换端口。
- 访问路径必须是 `/metrics`。

## CLI 参数错误

正确格式：

```powershell
.\netvision-pro.exe cli speedtest --json --duration 10 --down 6 --up 4
```

参数范围：`--duration` 为 5–30，`--down` 为 1–16，`--up` 为 1–8。`--node` 需要 HTTPS 地址；`--no-save` 仅影响本次 CLI 执行，不会删除已有历史。

## 仍然无法定位问题

提交 Issue 时请附上：

- Windows 版本和应用版本。
- 问题发生的页面和操作步骤。
- 是否只影响某个节点或协议。
- 脱敏后的错误文本、测速状态和诊断结果。

不要上传 `settings.json`、原始诊断截图、完整公网地址或包含令牌的文件。
