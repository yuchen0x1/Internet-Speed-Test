# v1.12.0 发布产物暴露面复核

## 1. 总览

对本地签名发布构建的 `dist/` 和 Windows 主程序运行 `reverse-engineering-exposure-audit` 静态扫描器，并人工核查更新、签名和发布文件范围。web 自动评分 100/A；native 自动评分 69/C。评分只用于启发式排序，不是安全认证，下面明确标注误报与剩余问题。

本次发布不包含本机测速截图、数据库、设置、私钥、密码、PDB、原始扫描报告或测试缓存。公开仓库采用 MIT 许可证，源码本身公开，不以代码混淆作为保密边界。

| --- | --- | --- | --- |

## 3. 逐项证据与措施

- 构建沿用 `sourcemap: false` 和 Rust release `strip = true`。仅上传安装包、更新签名、更新清单与 SHA-256 清单；签名私钥仅由既有本机受保护目录或 Actions Secrets 提供。
- 自定义网络目标和本机端点属于产品公开能力；127.0.0.1 的命中经过人工核对，不按内部基础设施泄露上报。
- 缺少 Authenticode 是现存限制，未伪造证书或抹去警告。配置有效 Windows 代码签名证书是后续事项。
- v1.12.0 启用 `requireSignedVersion`。使用 updater 同款 minisign-verify 库，验证 NSIS 文件与内置公钥匹配、签名绑定版本 1.12.0；修改文件字节会验签失败，错误版本也被拒绝。依据为 [Tauri updater 文档](https://v2.tauri.app/plugin/updater/) 及实际锁定插件/CLI 实现。
- 原始扫描报告和校验工具仅保留在 `src-tauri/target/`，不纳入发布；本报告去除构建机绝对路径和原始二进制字符串。

## 4. 客户端无法解决的问题

本应用无付费授权/订阅放行逻辑，也没有以客户端 `isPro` 等标志授权的业务后端。测速算法按项目许可证公开，无需加壳或反调试。M-Lab 临时令牌运行时仍由客户端持有，进程内存不能当作永久凭证保险箱；长期私钥与第三方账号凭证不得随客户端分发。

签名验证能约束更新包来源与版本，不能证明测量节点本身可信、所有依赖无漏洞或安装后一定成功。旧客户端发现、安装并启动新版本的完整链路未由本次静态审计替代。

## 5. 修复顺序

- P0：本轮未发现需要从分发包移除的真实长期凭证；持续检查提交和上传文件范围。
- P1：保持签名校验及版本绑定，避免旧包被更新清单伪装为新版本；后续配置真实 Authenticode 证书。
- P2：评估 CFG 与更全面的原生二进制加固，并针对 Windows 安装、休眠/网络变化及长期使用另行验收。
