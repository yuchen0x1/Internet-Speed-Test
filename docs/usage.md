# 使用指南

本文对应 NetVision Pro v1.12.0 的 Windows 桌面版，页面名称以当前应用界面为准。

## 第一次测速

1. 启动应用后打开“网络测速”。
2. 默认使用自动优选节点。自动优选会综合延迟、可用性和下载能力，不按地理距离直接决定。
3. 点击“重新测速”，等待准备、延迟、下载、上传和质量阶段完成。
4. 完成后查看仪表盘、下载/上传峰值、延迟、抖动、丢包和质量结果。
5. 需要复核链路时打开“网络质量”，查看空闲与负载延迟对比。

测速过程中的“停止”会取消当前任务；开启自动保存时，完成、取消和失败的任务都会按实际状态写入历史。

取消的测试保留实际已采集样本，但不生成完整网络质量评级。质量图中的未知丢包/未测上传不会按实测分数绘制。

如果磁盘空间或权限导致保存失败，页面会保留本次真实结果并显示“本次结果尚未保存”；CLI 的 JSON 包含 `history_save_error`，同时向 stderr 写入保存警告。测量是否成功与是否保存是独立状态。

## 历史日期、统计与导出

- 起止日期按本地日历计算，结束日期包含全天。例如同填 `2026-11-07` 会查询该天午夜到深夜的记录。
- 可选择“今天”“近 7 天”“近 30 天”，或“全部日期”移除筛选。起始晚于结束时会提示调整，并禁用导出。
- 统计卡覆盖整个筛选范围；速度与延迟均值只使用成功测试，上传均值跳过未知值，真实 0 值仍参与计算。
- 日均对比、热力图和趋势只展示已加载记录。默认加载 100 条，可继续“加载更多”；趋势最多取已加载成功记录中最近 40 条，时间从左向右。
- CSV/JSON 导出使用当前日期及排序，最多导出 5000 条，超过会明确提示截断。HTML 报告仍针对单条记录。
- “刷新记录”重新读取本地历史，读取失败可“重试加载”。更改日期后，旧请求的迟到结果不会覆盖新范围。
- “清空”仍删除整个历史库，不受当前筛选影响；请阅读确认框，所需记录先导出备份。

## 各页面用途

| 页面 | 用途 |
| --- | --- |
| 网络测速 | 执行多流测速，查看实时曲线、阶段事件和结果摘要。 |
| 网络质量 | 基于最近一次测速分析延迟、抖动、Bufferbloat、丢包和稳定性。 |
| 网络诊断 | 检查本地网卡、网关、DNS、TCP、HTTPS、IPv6、ICMP、NAT 和路由。 |
| 测速历史 | 筛选、排序、回放历史详情，并导出 CSV、JSON 或 HTML 报告。 |
| 测速节点 | 探测、收藏、切换和添加 HTTPS 节点。 |
| 批量拨测 | 对多个主机执行并发 ICMP 探测，查看最快、最慢、平均和丢包。 |
| 网络监控 | 查看整机网卡实时收发、累计流量和连续 Ping 曲线。 |
| 设置与关于 | 调整测速、监控、通知、隐私、历史和 Prometheus 配置。 |

## 选择节点

打开“测速节点”后可以：

- 点击“重新检测节点”更新延迟和可用性。
- 点击节点的“使用”切换手动测速节点。
- 点击“自动优选”恢复自动选择。
- 通过“添加节点”添加自建 LibreSpeed HTTPS 服务。
- 内网 HTTP 节点必须在添加时明确开启“允许 HTTP”，才能手动使用；删除当前手动节点后会回到自动优选。

自定义节点必须使用 HTTPS。节点页会显示 Cloudflare、LibreSpeed 和 M-Lab NDT7 的实际探测状态；不可达节点不会被伪装成可用。

## 网络诊断

“网络诊断”页将本地信息与主动检测分开：

- 本地网络区域展示网卡、协商速率、网关、DNS、MTU 和接口数量。
- DNS、网关、TCP、HTTPS、IPv6、路由、NAT 和服务连通性卡片需要点击“开始检测”后执行。
- “自定义 ICMP Ping”可输入主机名或 IP 发送 8 个数据包。
- “路由追踪”使用系统 tracert；不可达的跳会如实显示超时。

检测结果受目标策略、运营商线路和本机防火墙影响；“未知”不代表成功，也不代表失败。

## 批量拨测

在目标列表中每行输入一个主机名或 IP，选择每个目标的发包数，然后点击“开始拨测”。页面会显示：

- 当前完成进度和目标数。
- 最快、最慢、整体平均延迟。
- 每个目标的最新、最快、最慢、平均、发包、丢包和走势。
- 系统 DNS 与公共 DNS 的域名解析分布。

批量拨测使用真实 ICMP 探测；目标禁 ping 或中间设备丢弃 ICMP 时，结果可能出现超时或丢包。

## 历史与导出

“测速历史”默认按最新记录排序，可按日期筛选。每条记录支持详情回放、HTML 报告和删除；页面顶部支持 CSV、JSON 导出和清空历史。

导出由本机生成，默认最多导出最近 5000 条记录。历史保留期在“设置与关于”页调整，清理在应用启动时执行。

## 网络监控

“网络监控”页每秒读取网卡字节计数并计算收发速率，显示整机真实流量，不等同于单次测速流量。可以切换 1 分钟、5 分钟、15 分钟或 1 小时窗口，也可以暂停页面采样。

连续 Ping 监测需要输入目标后点击“开始监测”。红色丢包点代表该次 ICMP 探测未取得 RTT。

## 设置建议

- 普通测速：自动优选、10 秒、下载 6 路、上传 4 路、自动保存开启。
- 排查抖动：打开“网络质量”，同时观察空闲与下载/上传负载延迟。
- 长期观察：保持后台监控开启，按需要打开计划测速和桌面通知。
- 隐私优先：关闭“显示公网 IP 与 ISP”；关闭后应用不会主动查询公网地址。
- 监控集成：开启 Prometheus 指标导出后，只监听 `127.0.0.1`。

## CLI

在应用目录执行：

```powershell
.\netvision-pro.exe cli speedtest --json --duration 10 --down 6 --up 4
```

`--duration` 范围为 5–30 秒，`--down` 范围为 1–16，`--up` 范围为 1–8。`--precision` 开启精度模式，`--node` 指定 HTTPS 节点，`--no-save` 禁止写入历史。进度到 `stderr`，结果到 `stdout`。
